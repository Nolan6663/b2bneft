# Почта на домене texzakaz.ru — план перевода

**Дата:** 2026-07-30
**Зачем:** сейчас платформа пишет с бесплатного ящика `info.texzakaz@yandex.com`. Отсюда три ограничения: потолок примерно 20 писем в сутки (из-за него холодная рассылка растянута на месяцы), адрес отправителя не совпадает с доменом площадки, и сам `texzakaz.ru` **не может принимать почту вообще** — MX-записи нет, поэтому любой адрес вида `info@texzakaz.ru` отскакивает.

## Что уже сделано в коде

- Адрес публикуется из одного места — `scripts/legal-data.js`, поле `email`. После смены достаточно поправить его и прогнать `npm run sync:legal`: футер на 11 страницах обновится сам.
- Отправка полностью на переменных окружения: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `EMAIL_FROM`, `OUTREACH_REPLY_TO`. Смена ящика — это правка `.env` на VPS, не правка кода.
- Дефолты отправителя в `server.js` и `scripts/outreach.js` приведены к рабочему ящику: если переменная потеряется, письма уйдут с живого адреса, а не с мёртвого `noreply@texzakaz.ru`.

## Шаг 1. Подключить домен к Яндекс 360

1. Завести организацию в Яндекс 360 для бизнеса, добавить домен `texzakaz.ru`.
2. Подтвердить владение. Яндекс предложит три способа: TXT-запись в DNS, HTML-файл в корне или мета-тег. **Проще всего файл** — в проекте уже есть готовый механизм: список в `server.js` (рядом с `yandex_3fbc490e3bd5d37d.html` и `googleefff6b0475352b2b.html`), достаточно положить файл в корень репозитория и дописать его имя в тот же массив. Раздача идёт по белому списку, без записи в массиве будет 404.
3. Создать ящик `info@texzakaz.ru`. Дополнительные (`billing@`, `support@`) — по необходимости; сейчас на сайте везде один адрес.

## Шаг 2. DNS-записи

Добавляются в панели регистратора домена. Значение DKIM берётся в Яндекс 360 после подключения домена — оно уникальное, подставить чужое нельзя.

| Тип | Имя | Значение | Примечание |
|---|---|---|---|
| MX | `@` | `mx.yandex.net.` приоритет `10` | без неё домен не принимает почту |
| TXT | `@` | `v=spf1 redirect=_spf.yandex.net ~all` | SPF: кто вправе слать от имени домена |
| TXT | `mail._domainkey` | ключ из панели Яндекс 360 | DKIM: подпись писем |
| TXT | `_dmarc` | `v=DMARC1; p=none; rua=mailto:info@texzakaz.ru` | DMARC: сначала только отчёты |

Проверка после распространения записей (обычно от 15 минут до нескольких часов):

```
nslookup -type=MX texzakaz.ru 8.8.8.8
nslookup -type=TXT texzakaz.ru 8.8.8.8
nslookup -type=TXT _dmarc.texzakaz.ru 8.8.8.8
nslookup -type=TXT mail._domainkey.texzakaz.ru 8.8.8.8
```

Через две-три недели, когда в отчётах DMARC не будет чужих отправок, ужесточить политику до `p=quarantine`, позже до `p=reject`.

## Шаг 3. Переключить платформу

На VPS в `/var/www/neft/.env`:

```
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USER=info@texzakaz.ru
SMTP_PASS=<пароль приложения из Яндекс ID, не пароль от аккаунта>
EMAIL_FROM=info@texzakaz.ru
OUTREACH_REPLY_TO=info@texzakaz.ru
```

Затем:

```
pm2 restart neft
```

Обычные переменные `.env` подхватываются при перезапуске. Полное пересоздание процесса (`pm2 delete` + `pm2 start`) нужно только при правке `ecosystem.config.js` — здесь не требуется.

## Шаг 4. Обновить адрес на сайте

В `scripts/legal-data.js` заменить `email` на `info@texzakaz.ru`, затем:

```
npm run sync:legal
npm run check
```

Синк обновит футер на всех страницах, гейт проверит, что ничего не разошлось. Отдельно проверить `settings.html` и `tariff.html` — там адрес указан текстом.

## Шаг 5. Разгон рассылки

Домен новый для почтовых систем: если сразу дать 200 писем в день, репутация просядет и письма пойдут в спам. Разгонять постепенно, следя за отказами через `node scripts/outreach-stats.js`:

| Период | Лимит в день |
|---|---|
| Первая неделя | 20 (как сейчас) |
| Вторая неделя | 50 |
| Третья неделя | 100 |
| Дальше | 150–200, если доля ошибок в сводке близка к нулю |

Лимит меняется в кроне: `crontab -e`, аргумент `--limit` у `scripts/outreach.js`.

Признаки, что разгон пора остановить: в сводке растёт доля статусов, отличных от `sent`; в DMARC-отчётах появляются жалобы; ответы заводов перестают приходить совсем.

## Что проверить перед тем, как считать переезд завершённым

1. `https://texzakaz.ru/robots.txt` и футер сайта показывают новый адрес.
2. Письмо на `info@texzakaz.ru` доходит — домен принимает почту.
3. Тестовое письмо платформы приходит с подписью DKIM: `node scripts/outreach.js --test <своя почта>` на VPS, затем в полученном письме посмотреть заголовки — должны быть `dkim=pass` и `spf=pass`.
4. Регистрация нового пользователя присылает письмо подтверждения с нового адреса.
