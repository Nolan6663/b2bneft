## Открытый вопрос, с него продолжать

**Генерация ТЗ падает на проде: `500 «Не удалось разобрать ответ модели»`.**

- Воспроизводится стабильно: три разных запроса (манжеты РТИ, фланцы 09Г2С, шкаф НКУ) — все три `500`.
- **Локально с тем же ключом и той же моделью всё работает**: `generateProcurementTz` возвращает корректный JSON, проверено запуском `lib/ai-client.js` напрямую.
- Значит дело не в промпте и не в разборе, а в среде на VPS. Главные подозреваемые:
  1. запрос к GigaChat с сервера падает по сертификату (российский УЦ) — локально проверка отключалась через `NODE_TLS_REJECT_UNAUTHORIZED=0`, на сервере нужен корневой сертификат Минцифры;
  2. в `/var/www/neft/.env` другие значения `AI_TZ_MODEL` / `GIGACHAT_SCOPE`, чем в локальном `.env`.
- Следующий шаг — посмотреть, что именно отвечает модель на сервере:

```
! ssh ПОЛЬЗОВАТЕЛЬ@ХОСТ "pm2 logs neft --lines 80 --nostream | grep -i -A5 'generate-tz'"
```

Разбор ответа при этом уже усилен: при первой неудаче идёт повтор с требованием голого JSON
(`lib/ai-client.js`), плюс чек-лист из объектов больше не превращается в `[object Object]`.

## Известные ограничения (не поломки)

- **Почта на домене не поднята**: MX нет, письма идут с бесплатного ящика, потолок ~20 в сутки. План — `docs/ops-mail-domain.md`, первый шаг: TXT-запись в Selectel.
- **AI-поиск по каталогу** отвечает `503`: пустой `GEMINI_API_KEY`.
- **Онлайн-оплаты нет**, тариф «Ранний доступ».
- **Активных закупок в базе ноль.**
- Сравнение КП требует минимум двух предложений, бенчмарк — активной закупки: оба `400` по делу.
