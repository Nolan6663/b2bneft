# Глобальный проход по сайту: вёрстка и AI-слоп

**Дата:** 2026-08-01
**Статус:** дизайн согласован, план не написан
**Ветка:** от `master` после `9329ab2`

## Зачем

Публичная часть texzakaz.ru росла кусками: категории генерятся скриптом, лендинг правился руками, карта чинилась вчера ночью. Накопились две разные проблемы, которые до сих пор пытались решать одним движением и потому не дорешали ни одну.

Первая — **декоративный слоп**: мягкие цветные тени, pill-радиусы, градиенты. Признак генерённого интерфейса, чужой для площадки, которая продаёт себя как инженерный инструмент. Часть таких правок уже проходила (`79c72f7 style(seo): drop the soft glow and the shimmer on listing pages`), но точечно — по страницам, а не по теме, поэтому маркеры остались.

Вторая — **вёрстка на узких экранах**. Вчера карта показала, чего стоит доверять коду вместо снимка: три коммита подряд (`5106ca8`, `ff02586`) ушли на то, чтобы KPI-сетка встала в 2×2 на телефоне, потому что тема перебивала правку через `!important`. Остальные 16 страниц на 390px никто глазами не смотрел.

Третья, поменьше — **водянистые тексты**: заголовки ни о чём, триплеты «наших преимуществ», обещания без цифр.

## Слой 1. Тема

Единственный файл с массовыми маркерами — `assets/theme-v2.css` (124 КБ): 19 мягких теней, 11 pill-радиусов, 7 градиентов. `assets/css/tokens.css`, `assets/zakupki-cat.css` чисты — маркеров ноль, трогать нечего.

**Оставляем осознанно** (перечислено, чтобы не переспорить это на ревью):

- тени модалок и оверлеев — глубина диалога, не декор;
- шиммер скелетонов (2094, 2429, 2817) — индикатор загрузки;

- 11 совпадений `translateY(-` — это центрирование `top:50%` и въезд дропдаунов/модалок. Hover-подпрыгиваний в коде нет: вычищены прошлыми проходами.

## Слой 2. Страницы

Остатки, которых нет в теме: `landing.html` (10 теней, 11 градиентов — половина проекта), `map.html`, `login.html`, `partners.html`, `catalog.html`, `supplier-public.html`, `tariff.html`, `dlya-postavshchikov.html`, `delivery.html`. Правки того же вида, что в слое 1.

Категории (`zakupki/*.html`) правятся **только через генератор**: источник — `seo/categories-data.js`, сборка — `npm run sync:categories`. Правка HTML напрямую затрётся следующим прогоном.

Футер на всех страницах — тоже генерируемый: источник `scripts/legal-data.js`, сборка `npm run sync:legal`, гейт сверяет побайтово.

## Слой 3. Вёрстка

Снимки 390 и 1440 по всем 17 страницам, разбор глазами. Ищем: горизонтальный скролл, налезание текста, сетку в одну колонку там, где место на две (и наоборот), обрезанные кнопки, нечитаемо мелкий шрифт, разъехавшиеся таблицы, элементы, вылезающие за вьюпорт.

Каждая находка — отдельная правка с подтверждающим снимком после. Правка без снимка не считается сделанной.

Эталонные снимки берутся **с прода**: локальный `.env` смотрит на старую Render-базу в Огайо, локальный сервер поднимется, но с чужими данными. Правки проверяются локально, финальная сверка — на проде после деплоя.

## Слой 4. Тексты

Водянистые заголовки, триплеты «наших преимуществ», обещания без цифр, канцелярит.

Не трогаем то, что заведено под SEO осознанно: H1 категорий, FAQ-разметку, JSON-LD. Юртексты (`privacy.html`, `terms.html`) — по смыслу не трогаем, только вёрстку.

## Проверка

После каждого слоя:

```
npm run check
npm test
```

Базовая линия на 2026-08-01: **123 юнита, 0 падений**.

Правки только через `[IO.File]::WriteAllText` в UTF-8 — прошлая массовая замена покорёжила кириллицу.

Снимки до/после снимаются по **всем** страницам, включая нетронутые, и по кабинету. Причина — каскад: в `theme-v2.css` 15 объявлений с селектором `.kpi-card` и несколько правил на `!important`. Правка темы может разъехаться там, где не ждёшь; вчерашняя история с KPI-сеткой ровно про это.

Коммит на слой. Деплой одним пушем в конце.

## Порядок и почему он такой

Тема первой. Если начать со страниц, постраничные правки конфликтуют с темой и переделываются заново — именно так проход выродился в прошлые разы. Вёрстка после чистки декора: убранная тень меняет метрики блока, снимать до этого бессмысленно. Тексты последними — они не двигают вёрстку.

## Готово, когда

1. В `theme-v2.css` не осталось мягких цветных теней и pill-радиусов из таблицы слоя 1; оставленное — только из списка «оставляем осознанно».
2. На 17 публичных страницах нет `linear-gradient` и мягких теней вне того же списка.
3. Снимки 390 и 1440 по всем 17 страницам сняты, найденные косяки вёрстки исправлены и подтверждены снимком после.
4. `npm run check` и `npm test` (123) зелёные.
5. Прод после деплоя выглядит как локальные снимки «после».

## Что вышло по факту (2026-08-01)

Проход закрыт коммитами `3eeb977`…`f3fdecf`. Четыре расхождения с тем, что предполагалось на входе:

1. **Четыре из семнадцати страниц гостю не показываются.** `catalog`, `partners`, `tariff`, `delivery` перекидывают незалогиненного на `/login` клиентским скриптом. Публичный проход их не покрывает — вёрстку этих страниц надо смотреть под учёткой, отдельной задачей. Их CSS-маркеры при этом вычищены: они правились по коду.
2. **`tokens.css` лежит в `assets/css/`, а не в `assets/`, и маркеров в нём нет.** Слой 1 свёлся к одному файлу — `theme-v2.css`.
3. **Градиенты в теме и на лендинге почти все законные:** чертёжная сетка и шиммер скелетонов. Из 24 совпадений слопом не оказалось ни одного — убирать было нечего.
4. **`.kp-rec-card` со свечением нашлась только при разборе** — в исходную таблицу слоя 1 не попала, вычищена вместе с остальными.

Единственный косяк вёрстки, найденный снимками: таблица третьих лиц в политике уносила документ на 194px вбок на 390px. Починена обёрткой со скроллом.

Регрессия закрыта тестом `tests/unit/no-slop.test.js`: он сканирует тему и 17 страниц, исключения перечислены поимённо с причиной. Снимки снимает `scripts/shoot-pages.js` — он же печатает горизонтальное переполнение и виновные элементы.
